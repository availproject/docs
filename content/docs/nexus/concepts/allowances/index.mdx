The Nexus SDK requires allowances.

Through allowances, a user permits the Nexus Vault contracts on the source chains
to collect their funds. The protocol uses these funds to settle the transaction
delivered on the destination chain.

- The SDK always approves the **minimum** amount the operation needs — it never grants unlimited approvals. There is no allowance hook to configure.
- Required approvals appear in the quote before anything is signed: `quote.allowances` lists the current, required, and missing allowance per source token, and `quote.plan.steps` includes an `erc20_approval` or `source_approval_signature` step where one is needed.
- Your app can show these to the user from the `onIntent` hook passed in `options.hooks`.

```typescript
await client.swapWithExactOut(params, {
  hooks: {
    onIntent: ({ quote, allow }) => {
      for (const a of quote.allowances) {
        console.log(a.chainId, a.tokenAddress, a.spender, a.deficitRaw);
      }
      allow();
    },
  },
});
```

Until the required allowance is in place, the Nexus Vault contracts on the source chains cannot collect the user funds for Nexus operations.

<ThemedImage light="/img/nexus/allowances-light.png" dark="/img/nexus/allowances-dark.png" alt="Token Allowances" />

By approving allowances for chain abstraction on the source chains, users can:

* Spend anywhere with funds from two or more source chains.
* Bypass bridging to enable liquidity on the destination chain.
* Transact on newer chains with zero or insufficient liquidity.

<Callout type="warning">
Setting an allowance is normally an on-chain transaction, so users **pay a gas fee** for it. Where a token supports EIP-2612 permits, the SDK uses a signed permit instead — a gasless signature — so no separate approval transaction is needed.
</Callout>

## How Allowances Work

Here is how allowances enable chain abstracted transactions:

1. The SDK requests a quote and presents it to the user: the amounts to collect per source chain, the destination amount, fee details, and any required allowances. The user approves or rejects it via the `onIntent` hook.
2. For any source token whose current allowance is below what the operation needs, the SDK requests the minimum required approval.
3. Approvals are granted to the spender named in the quote (for native Nexus routes, the Nexus Vault contracts on the source chains) — via a regular ERC-20 approval, or a gasless EIP-2612 permit where the token supports it.
4. The user signs the intent. Solvers then supply liquidity on the destination chain.
5. The protocol settles with the solvers using the funds collected from the source chains.

See [Review quotes](/docs/nexus/nexus-sdk/reference/swap-methods/review-quotes) for the full `onIntent` and `IntentQuote` shapes.
