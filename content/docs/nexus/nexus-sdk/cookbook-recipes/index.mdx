The Cookbook Recipes are written to show developer patterns on how the SDK is expected to be used by a developer or an LLM agent.

<Callout type="info">
These recipes target `@avail-project/nexus-core` v3. Upgrading from v2? The `bridge*`, `simulate*`, `calculateMaxFor*`, and `getBalancesForBridge` methods were removed. See the [v2 to v3 migration guide](/docs/nexus/migration/sdk-v2-to-v3).
</Callout>


## Getting a client

Every recipe assumes an initialized `NexusClient`. Create one with `createNexusClient()`, call `initialize()` to load the chain catalog, then attach a wallet with `setEVMProvider()`. Call `destroy()` when you are done.

```typescript title="TypeScript"
import { createNexusClient } from '@avail-project/nexus-core';

const client = createNexusClient({ clientId: 'your-app-name', network: 'mainnet' });

await client.initialize();                       // load the chain catalog
await client.setEVMProvider(window.ethereum);    // attach an EIP-1193 wallet

// ... use the client ...

client.destroy();                                // clean up when finished
```

<Callout type="info">
`clientId` is a required, stable identifier for your app. Catalog queries and exact-input quote previews need only `initialize()`; balances and execution also need a wallet. Create a fresh client when the connected account or provider changes. The `testnet` network supports standalone `execute()` only; swaps and intent catalog helpers reject with `ENVIRONMENT_NOT_SUPPORTED`.
</Callout>

All recipes below use these two token references (USDC on Ethereum and Base):

```typescript title="TypeScript"
const ethUsdc = { chainId: 1, tokenAddress: '0xA0b86991c6218b36c1d19d4a2e9eb0cE3606eB48' } as const;
const baseUsdc = { chainId: 8453, tokenAddress: '0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913' } as const;
```


## SDK operations

### How to preview a quote without executing?
There are no `simulate*` methods in v3. Every swap quotes first and passes the quote to `options.hooks.onIntent`. The operation waits until you call `allow()` or `deny()`, so you can render the quote and let the user decide. Calling `deny()` rejects the operation with a `UserActionError`.

```typescript title="TypeScript"
import { UserActionError, type IntentQuote } from '@avail-project/nexus-core';
import { parseUnits } from '@avail-project/nexus-core/utils';

const destinationToken = await client.getToken(baseUsdc);
let previewed: IntentQuote | undefined;

try {
  await client.swapWithExactOut(
    {
      toChainId: baseUsdc.chainId,
      toTokenAddress: baseUsdc.tokenAddress,
      toAmountRaw: parseUnits('100', destinationToken.decimals),
    },
    {
      hooks: {
        onIntent: ({ quote, deny }) => {
          previewed = quote;
          deny(); // preview only; call allow() to execute instead
        },
      },
    },
  );
} catch (error) {
  if (!(error instanceof UserActionError)) throw error;
}

console.log(previewed?.input, previewed?.output, previewed?.fees);
```

`swapWithExactIn` can also preview a rate **before a wallet is connected**. Initialize the client, skip `setEVMProvider()`, and check `execution` in the hook:

```typescript title="TypeScript"
const sourceToken = await client.getToken(ethUsdc);

await client
  .swapWithExactIn(
    {
      sources: [{ ...ethUsdc, amountRaw: parseUnits('25', sourceToken.decimals) }],
      toChainId: baseUsdc.chainId,
      toTokenAddress: baseUsdc.tokenAddress,
    },
    {
      hooks: {
        onIntent: ({ quote, execution, deny }) => {
          if (!execution.possible && execution.cause === 'not-connected') {
            console.log('You would receive at least', quote.output.minAmountRaw);
          }
          deny();
        },
      },
    },
  )
  .catch(() => {}); // a disconnected preview never resolves successfully
```

<Callout type="info">
A disconnected preview stays disconnected for the whole call. After the user connects, start a new swap call to get a fresh, executable quote. See [Review quotes](/docs/nexus/nexus-sdk/reference/swap-methods/review-quotes).
</Callout>

### How do I get source and destination information from a quote?
An `IntentQuote` lists the funding legs in `input`, the destination in `output`, and a per-source decision in `sourceVerdicts`. Amounts ending in `Raw` are `bigint`. USD amounts are decimal strings.

```typescript title="TypeScript"
import { formatUnits } from '@avail-project/nexus-core/utils';
import type { IntentQuote } from '@avail-project/nexus-core';

async function describeQuote(quote: IntentQuote) {
  for (const leg of quote.input) {
    const token = await client.getToken({ chainId: leg.chainId, tokenAddress: leg.tokenAddress });
    console.log(
      `${formatUnits(leg.totalRequiredRaw, token.decimals)} ${leg.tokenSymbol} from chain ${leg.chainId}`,
      `(~$${leg.totalRequiredUsd}, deposit fee ${formatUnits(leg.depositFeeRaw, token.decimals)})`,
    );
  }

  const out = await client.getToken({ chainId: quote.output.chainId, tokenAddress: quote.output.tokenAddress });
  console.log('Receive:', formatUnits(quote.output.amountRaw, out.decimals), out.symbol);
  console.log('Guaranteed minimum:', formatUnits(quote.output.minAmountRaw, out.decimals));

  // Which wallet sources were selected, unused, or unroutable (and why)
  for (const verdict of quote.sourceVerdicts) {
    console.log(verdict.chainId, verdict.tokenSymbol, verdict.state, verdict.reason ?? '');
  }

  console.log('Provider:', quote.provider, 'Expires:', new Date(quote.expiresAt * 1000));
  console.log('Steps:', quote.plan.steps.map((step) => step.type));
}
```

Call `describeQuote(quote)` from your `onIntent` hook or from a `quote` event.

### How to get the fees incurred from a quote?
Every `IntentQuote` has a `fees` object. Each fee has a raw `bigint` amount and a USD string. Raw fee amounts are in the funding token's units, so format them with that token's decimals.

```typescript title="TypeScript"
onIntent: ({ quote, allow }) => {
  const { fees } = quote;

  console.log('Deposit:', fees.depositUsd);
  console.log('Fulfillment:', fees.fulfillmentUsd);
  console.log('Protocol:', fees.protocolUsd);
  console.log('Solver:', fees.solverUsd);

  // Per-source deposit fees, in each source token's raw units
  quote.input.forEach((leg) => console.log(leg.chainId, leg.depositFeeRaw, leg.depositFeeUsd));

  allow();
},
```

### How to bridge the same token across chains?
There is no `bridge()` method in v3. Use either swap method with the **same asset's address on each chain**. Exact output specifies what to receive; exact input specifies what to spend.

```typescript title="TypeScript"
const token = await client.getToken(baseUsdc);

// Receive exactly 100 USDC on Base, funded from USDC on Ethereum
const result = await client.swapWithExactOut({
  sources: [ethUsdc],
  toChainId: baseUsdc.chainId,
  toTokenAddress: baseUsdc.tokenAddress,
  toAmountRaw: parseUnits('100', token.decimals),
});

console.log(result.intentId, result.intentExplorerUrl);
```

Omit `sources` to let the SDK fund the route from any eligible wallet balance. See [Bridge tokens](/docs/nexus/nexus-sdk/get-started/bridge-tokens).

### How to spend the maximum usable balance?
`calculateMaxForBridge` and `calculateMaxForSwap` were removed. Read `usableBalanceRaw` from `getBalances()` and pass it as the exact-input amount. `usableBalanceRaw` already excludes the gas reserve, so a native-token source never spends the full wallet balance.

```typescript title="TypeScript"
const balances = await client.getBalances();
const source = balances.find(
  (b) => b.chainId === ethUsdc.chainId && b.tokenAddress.toLowerCase() === ethUsdc.tokenAddress.toLowerCase(),
);

if (!source?.usable || source.usableBalanceRaw === 0n) {
  throw new Error('Nothing to spend on this source');
}

await client.swapWithExactIn({
  sources: [{ chainId: source.chainId, tokenAddress: source.tokenAddress, amountRaw: source.usableBalanceRaw }],
  toChainId: baseUsdc.chainId,
  toTokenAddress: baseUsdc.tokenAddress,
});
```

<Callout type="warn">
With several exact-input sources, all sources and the destination must share one provider. Use [`getAvailableSourceTokens`](/docs/nexus/nexus-sdk/reference/balances-and-tokens/token-catalog) to keep selections compatible. A quote can still fail when a full balance cannot cover deposit fees. See [Handle quote failures](#how-to-handle-quote-failures-with-getintentquotefailure).
</Callout>

### How to deposit with Relay provider execution?
Set `useProviderDestinationExecution: true` on `swapAndExecute` and Relay approves and executes the destination call during fulfillment. The wallet sends no destination transaction. In this mode `beforeExecute` runs **before review** (and again on every refresh). Use `executeAmountRaw` there, which is the fixed execution budget, to encode amount-sensitive calldata.

```typescript title="TypeScript"
declare const vault: `0x${string}`;
declare function buildDepositData(amountRaw: bigint): `0x${string}`;

const sourceToken = await client.getToken(ethUsdc);

const deposited = await client.swapAndExecute(
  {
    tradeType: 'exactInput',
    sources: [{ ...ethUsdc, amountRaw: parseUnits('50', sourceToken.decimals) }],
    toChainId: baseUsdc.chainId,
    toTokenAddress: baseUsdc.tokenAddress,
    execute: {
      to: vault,
      gas: 350_000n,
      tokenApproval: { toTokenAddress: baseUsdc.tokenAddress, amount: 0n, spender: vault },
    },
  },
  {
    useProviderDestinationExecution: true,
    beforeExecute: async ({ executeAmountRaw }) => ({ data: buildDepositData(executeAmountRaw) }),
    hooks: {
      onIntent: ({ intent, allow }) => {
        console.log(intent.executionMode, intent.executeRequirement.token.amountRaw);
        allow(); // call after the user confirms
      },
    },
  },
);

if (deposited.executionMode === 'provider') {
  console.log(deposited.executeAmountRaw, deposited.swapResult.intentExplorerUrl);
}
```

<Callout type="warn">
The destination contract must support depositing on behalf of the recipient, because its caller is Relay's router. Unsupported routes reject before signing and never fall back to wallet execution. See [Provider destination execution](/docs/nexus/nexus-sdk/reference/swap-methods/swap-and-execute#provider-destination-execution) for the limits on execution budget, funding legs, and native value.
</Callout>

### How to handle quote failures with `getIntentQuoteFailure`?
When the middleware cannot route a quote, the rejected `NexusError` carries structured diagnostics. `getIntentQuoteFailure(error)` returns them as an `IntentQuoteFailure`, or `null` for any other error. Branch on `subcode` and inspect `sourceVerdicts`. Do not parse message text.

```typescript title="TypeScript"
import { getIntentQuoteFailure } from '@avail-project/nexus-core';

try {
  await client.swapWithExactIn(params);
} catch (error) {
  const failure = getIntentQuoteFailure(error);
  if (!failure) throw error;

  switch (failure.subcode) {
    case 'VALUE_ABOVE_CEILING':
      console.info(`Reduce the amount. Limit: $${failure.details.maxValueUsd}`);
      break;
    case 'INPUT_BELOW_DEPOSIT_FEE':
      console.info('Increase the source amount to cover the deposit fee.');
      break;
    case 'NO_ROUTE_TO_DESTINATION':
      console.info('Choose a destination supported by the allowed providers.');
      break;
    case 'INSUFFICIENT_BALANCE':
      console.info('Fund the wallet or choose different sources.');
      break;
    case 'INSUFFICIENT_APPROVAL_GAS':
      console.info('Add native gas on the source chain or choose another source.');
      break;
    case 'NO_ROUTABLE_SOURCE':
    default:
      for (const v of failure.sourceVerdicts.filter((v) => v.state === 'unroutable')) {
        console.info(`${v.tokenSymbol} on ${v.chainId}: ${v.reason}${v.detail ? ` (${v.detail})` : ''}`);
      }
  }

  if (!failure.retryable) {
    // Change the request (amount, sources, destination) before trying again.
  }
}
```

<Callout type="info">
For codes that are not quote failures (wallet not connected, user denial, execution errors), branch on `error.code` with `ERROR_CODES`. See [Hooks and errors](/docs/nexus/nexus-sdk/reference/hooks-and-errors).
</Callout>

### How to view a wallet's intent history?
Call `client.listIntents({ page?, status? })` to fetch the connected wallet's intents. It returns `{ intents, total }`. The page size is fixed at 20, so increment `page` to paginate. Filter with the exported `IntentStatus` constant.

```typescript title="TypeScript"
import { IntentStatus } from '@avail-project/nexus-core';

const { intents, total } = await client.listIntents();
const page2 = await client.listIntents({ page: 2 });
const fulfilled = await client.listIntents({ status: IntentStatus.Fulfilled });

console.log(`Total intents: ${total}`);

for (const intent of intents) {
  // status: 'created' | 'deposited' | 'fulfilled' | 'expired'
  console.log(intent.id, intent.provider ?? 'unknown', intent.status, intent.explorerUrl);
  if (intent.createdAt) console.log('  created', new Date(intent.createdAt * 1000));
}
```

## Chain & Token Utilities

<Callout type="info">
The SDK ships no hard-coded chain or token tables. Chains come from `client.getSupportedChains()` and tokens from the async catalog methods (`getTokens`, `getTokensByChain`, `getToken`). `client.chainList` remains for execution metadata, but its known-token list is not a full catalog. Use the catalog methods to look up tokens.
</Callout>

### How to get the list of supported chains?
`client.getSupportedChains()` returns cached chain metadata without token lists. Filter on `capabilities.intent` for swap chains and `capabilities.execute` for chains that support `execute()`.

```typescript title="TypeScript"
const chains = client.getSupportedChains();

const swapChains = chains.filter((chain) => chain.capabilities.intent);
const executeChains = chains.filter((chain) => chain.capabilities.execute);

chains.forEach((chain) => {
  console.log(`${chain.name} (${chain.id})`, chain.logo, chain.nativeCurrency.symbol, chain.providers);
});
```

<Callout type="info">
To list chains before you create a client, use the standalone helper: `import { getSupportedChains } from '@avail-project/nexus-core/utils'`, then `await getSupportedChains('mainnet', { clientId: 'your-app-name' })`. It returns a lighter shape: `id`, `name`, `logo`, `swapSupported`, `asSource`, and `asDestination`.
</Callout>

### How to get the chain ID or explorer of a supported chain?

```typescript title="TypeScript"
const base = client.getSupportedChains().find((c) => c.name === 'Base');
console.log(base?.id);           // 8453
console.log(base?.explorerUrl);  // explorer base URL, when provided

client.isSupportedChain(8453);   // true

// Hex chain ID for wallet_switchEthereumChain
const hexChainId = `0x${(8453).toString(16)}`; // "0x2105"
```

### How to get a token's address, decimals, logo, and name?
Search a chain's tokens with `getTokensByChain()` or resolve an exact token with `getToken()`. Each `IntentToken` has `address`, `symbol`, `name`, `decimals`, `isNative`, `verified`, `logo`, and `providers`.

```typescript title="TypeScript"
import { getFallbackTokenLogoDataUri } from '@avail-project/nexus-core';

// By symbol on one chain (verified tokens by default)
const page = await client.getTokensByChain(8453, { symbol: 'USDC', limit: 10 });
const usdc = page.tokens[0];
console.log(usdc?.address, usdc?.decimals, usdc?.name);

// Exact lookup by chain + address (also resolves unverified tokens)
const token = await client.getToken(baseUsdc);
const logo = token.logo ?? getFallbackTokenLogoDataUri(token.symbol);

// The native gas token comes from catalog metadata, never a hardcoded address
const base = client.getSupportedChains().find((c) => c.id === 8453);
const native = (await client.getTokensByChain(8453, { symbol: base?.nativeCurrency.symbol })).tokens.find(
  (t) => t.isNative,
);
```

<Callout type="info">
If a logo URL is missing or returns 404, `getFallbackTokenLogoDataUri(symbol)` returns a deterministic SVG data URI to use as a placeholder.
</Callout>

### How to paginate a token picker?
Catalog pages return `{ offset, limit, total }`. They default to offset 0 and limit 50, and the maximum limit is 1000. Advance by `offset + limit` while it is less than `total`, and reset the offset when the search or filters change.

```typescript title="TypeScript"
import type { IntentToken } from '@avail-project/nexus-core';

async function loadTokens(chainId: number, search: string, offset = 0) {
  const page = await client.getTokensByChain(chainId, { symbol: search || undefined, offset, limit: 50 });
  const hasMore = page.offset + page.limit < page.total;
  return { tokens: page.tokens, nextOffset: hasMore ? page.offset + page.limit : null };
}

// First page, then "Load more"
let { tokens, nextOffset } = await loadTokens(8453, 'US');
if (nextOffset !== null) {
  const more = await loadTokens(8453, 'US', nextOffset);
  tokens = [...tokens, ...more.tokens];
}
```

Compatibility pickers work the same way, with one difference. Their pages count candidates **before** filtering, so an empty page does not mean there are no later matches. For exact-input source pickers, pass the current selections so every source shares one provider, and deduplicate by chain ID plus address:

```typescript title="TypeScript"
const selected = [ethUsdc]; // keep selections outside the displayed page
const sourcePage = await client.getAvailableSourceTokens(baseUsdc, selected, { offset: 0, limit: 50 });

const seen = new Set<string>();
const options: IntentToken[] = [];
for (const group of sourcePage.groups) {
  for (const chain of group.chains) {
    for (const t of chain.tokens) {
      const key = `${t.chainId}:${t.address.toLowerCase()}`;
      if (!seen.has(key)) {
        seen.add(key);
        options.push(t);
      }
    }
  }
}
const hasMore = sourcePage.offset + sourcePage.limit < sourcePage.total;
```

<Callout type="info">
Returned tokens use `address`; selections and `TokenRef` use `tokenAddress`. For exact-output pickers, sources are alternatives, so call `getAvailableSourceTokens(destination, [], query)`. See [Token catalog](/docs/nexus/nexus-sdk/reference/balances-and-tokens/token-catalog).
</Callout>

## Balances

### How to fetch a wallet's balances?
`client.getBalances()` returns one `IntentBalance` per chain and token held by the connected wallet. `actualBalanceRaw` is the full wallet balance. `usableBalanceRaw` is what remains for routing after gas reserves. `valueUsd` values the usable balance and is `null` when no price is available.

```typescript title="TypeScript"
import { formatUnits } from '@avail-project/nexus-core/utils';

const balances = await client.getBalances();

for (const b of balances) {
  console.log(
    `${b.symbol} on ${b.chainId}:`,
    formatUnits(b.usableBalanceRaw, b.decimals), 'usable of',
    formatUnits(b.actualBalanceRaw, b.decimals),
    b.valueUsd === null ? '(no price)' : `~$${b.valueUsd.toFixed(2)}`,
    b.verified ? '' : '(unverified)',
    b.usable ? '' : '(not usable)',
  );
}
```

<Callout type="info">
`getBalancesForSwap()` is a deprecated alias of `getBalances()`, and `balanceRaw` is a deprecated alias of `usableBalanceRaw`. Results include unverified tokens, so respect `verified` and `usable` in your UI. See [getBalances](/docs/nexus/nexus-sdk/reference/balances-and-tokens/get-balances).
</Callout>

### How to show only Relay-supported balances?
Each `IntentBalance` lists the providers that support its token in `providers`. Filter on the client side:

```typescript title="TypeScript"
const balances = await client.getBalances();

const relayBalances = balances.filter(
  (b) => b.usable && b.usableBalanceRaw > 0n && b.providers.some((p) => p.id === 'relay'),
);
```

<Callout type="warn">
A `relay` entry in `providers` means the catalog lists the token for Relay. It does not guarantee that a particular route can run provider destination execution. That is decided per quote by `quote.supportsDestinationCalls` on the funding legs actually selected, and only one chain and token leg may fund a provider-executed route. Use this filter to narrow a picker, then rely on the quote (or the rejection) for the final answer.
</Callout>

## Events

### How and when to listen to Nexus events?
Pass `onEvent` in the options of any swap method or `swapAndExecute`. Events are an `IntentEvent` union keyed on `event.type`:

- `quote`: the current quote and plan. Emitted again after a refresh.
- `step`: a plan step moved to `started`, `completed`, or `failed`.
- `status`: intent lifecycle (`created`, `deposited`, `fulfilled`, `expired`) with per-source `legs`.

```typescript title="TypeScript"
import type { IntentEvent } from '@avail-project/nexus-core';

const onEvent = (event: IntentEvent) => {
  switch (event.type) {
    case 'quote':
      // Initialize a progress stepper from the plan
      console.log('Steps:', event.quote.plan.steps.map((s) => s.type));
      break;

    case 'step':
      console.log(`Step ${event.step.type}: ${event.state}`);
      if (event.state === 'failed') {
        console.error(event.errorDetails?.message, event.errorDetails?.code);
        // A committed attempt may still settle. Check status before retrying.
        console.log('Committed:', event.committed);
      }
      break;

    case 'status':
      console.log('Intent', event.intentId, event.status, event.substatus);
      for (const leg of event.legs) {
        console.log('  source', leg.sourceIndex, leg.status, leg.txExplorerUrl ?? '', leg.error ?? '');
      }
      break;
  }
};

const result = await client.swapWithExactIn(params, { onEvent });
```

<Callout type="info">
Event callback failures never interrupt the operation. Events cover funding only. For `swapAndExecute`, the returned promise also covers the destination contract call, so always await and catch it.
</Callout>

### How to review and approve intents?
Hooks are passed per operation through `options.hooks`. `onIntent` receives the quote with `allow()`, `deny()`, and `refresh(sources?)`. Without a hook, quotes are accepted automatically. There is no `onAllowance` hook. ERC-20 approvals always use the minimum required amount.

```typescript title="TypeScript"
await client.swapWithExactOut(params, {
  hooks: {
    onIntent: async ({ quote, execution, allow, deny, refresh }) => {
      if (!execution.possible) {
        console.warn('Cannot execute:', execution.cause, quote.executionWarnings);
      }

      // Optional: re-quote against different sources. Render the returned quote.
      // const updated = await refresh([{ chainId: 42161 }]);

      if (await userConfirmed(quote)) allow();
      else deny();
    },
  },
  slippageBps: 50, // integer 0–10000, or 'auto'
});
```

For `swapAndExecute`, the hook is also under `options.hooks.onIntent`, but it receives `intent` (a `SwapAndExecuteIntent`) instead of `quote`. It runs even when no swap is needed. `intent.quote` exists only when `intent.swapRequired` is true:

```typescript title="TypeScript"
await client.swapAndExecute(params, {
  hooks: {
    onIntent: ({ intent, allow }) => {
      console.log(intent.executionMode, intent.executeRequirement, intent.shortfall);
      if (intent.swapRequired) console.log(intent.quote.output);
      allow();
    },
  },
});
```

See [Review quotes](/docs/nexus/nexus-sdk/reference/swap-methods/review-quotes) for refresh semantics and quote expiry.

## Troubleshooting

### How to solve Vite polyfill issues?
If you see errors like `ReferenceError: Buffer is not defined` or `process is not defined`, Vite needs Node.js polyfills.

**Step 1: Install the polyfill plugin**

```bash filename="Terminal"
npm install vite-plugin-node-polyfills
```

**Step 2: Update vite.config.ts**

```typescript filename="vite.config.ts"
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { nodePolyfills } from 'vite-plugin-node-polyfills';

export default defineConfig({
  plugins: [
    react(),
    nodePolyfills({
      include: ['buffer', 'crypto', 'stream', 'util'],
      globals: {
        Buffer: true,
        global: true,
        process: true,
      },
    }),
  ],
  define: {
    global: 'globalThis',
  },
});
```

**Quick start alternative:** Clone the [Nexus Vite Template](https://github.com/availproject/nexus-vite-template) which has polyfills pre-configured.

### How to solve Turbopack issues in Next.js?
Turbopack (Next.js experimental bundler) has limited support for Node.js polyfills. If you encounter module resolution errors:

**Option A: Disable Turbopack (Recommended)**

Remove the `--turbo` flag from your dev script:

```json filename="package.json"
{
  "scripts": {
    "dev": "next dev"
  }
}
```

**Option B: Configure Webpack fallbacks**

```javascript filename="next.config.js"
/** @type {import('next').NextConfig} */
const nextConfig = {
  webpack: (config, { isServer }) => {
    if (!isServer) {
      config.resolve.fallback = {
        ...config.resolve.fallback,
        crypto: require.resolve('crypto-browserify'),
        buffer: require.resolve('buffer/'),
        stream: require.resolve('stream-browserify'),
      };
    }
    return config;
  },
};

module.exports = nextConfig;
```

Install required packages:

```bash filename="Terminal"
npm install crypto-browserify buffer stream-browserify
```

**Quick start alternative:** Clone the [Nexus Next.js Template](https://github.com/availproject/nexus-nextjs-template) which has proper configuration.

### How to fix "require is not defined" in browser?
This error occurs when code meant for Node.js runs in the browser. Solutions:

**1. Use ES module imports instead of require():**

```typescript
// Bad
const { createNexusClient } = require('@avail-project/nexus-core');

// Good
import { createNexusClient } from '@avail-project/nexus-core';
```

**2. Move Node.js-specific code to API routes or Server Components:**

```typescript filename="app/api/data/route.ts"
export async function GET() {
  // Node.js modules work here
  return Response.json({ data: 'ok' });
}
```

**3. Use dynamic imports for server-only code:**

```typescript
if (typeof window === 'undefined') {
  const serverModule = await import('server-only-module');
}
```
