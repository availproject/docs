In this guide you will create a Nexus client, initialize it, attach an EIP-1193 wallet provider, and fetch the user's balances across every supported chain. You will also learn which methods need a wallet, which networks are available, and how to handle account changes and cleanup.

## Prerequisites

- `@avail-project/nexus-core` installed in your project (see [Installation](/docs/nexus/nexus-sdk/get-started/installation))
- An [EIP-1193](https://eips.ethereum.org/EIPS/eip-1193) wallet (for example MetaMask) if you want to fetch balances or execute operations

## Step 1: Create the client

Create a client with `createNexusClient`. The only required field is `clientId`.

```typescript title="TypeScript"
import { createNexusClient } from "@avail-project/nexus-core";

const client = createNexusClient({
  clientId: "my-nexus-app", // required: stable, non-empty app identifier
  network: "mainnet",       // optional: 'mainnet' (default) | 'canary' | 'testnet'
});
```

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `clientId` | `string` | Yes | Stable, non-empty identifier for your application. `createNexusClient` throws a `ValidationError` if it is missing or blank. |
| `network` | `'mainnet' \| 'canary' \| 'testnet'` | No | Which Nexus deployment to use. Defaults to `'mainnet'`. |
| `debug` | `boolean` | No | Enables debug-level SDK logging. Defaults to `false`. |
| `analytics` | `AnalyticsConfig` | No | Product analytics settings. Pass `{ enabled: false }` to opt out. See [Analytics](#analytics). |

### Networks

| Value | Chains | What works |
| --- | --- | --- |
| `mainnet` | Mainnet chains | Everything: swaps, same-asset bridging, `swapAndExecute`, catalog, balances, and standalone `execute` |
| `canary` | Mainnet chains | Same as `mainnet`, against Avail's canary deployment. Use it only if the Avail team asks you to. |
| `testnet` | Testnet chains | Standalone `execute()` and `simulateExecute()` only |

<Callout type="warn" title="Testnet limitations">
On `testnet`, intent operations (`swapWithExactIn`, `swapWithExactOut`, `swapAndExecute`) and the async catalog helpers (`getTokens`, `getTokensByChain`, `getToken`, `getAvailableSourceTokens`, `getAvailableDestinationTokens`, `confirmRouteExists`, `getSupportedChainsForRoute`) reject with `ERROR_CODES.ENVIRONMENT_NOT_SUPPORTED`. Build and test swap and bridge flows on `mainnet` with small amounts.
</Callout>

## Step 2: Initialize

`initialize()` loads the supported chains and token catalog from the Nexus middleware. Call it once per client, before any other method.

```typescript title="TypeScript"
await client.initialize();

// Catalog methods work now, without a wallet.
const chains = client.getSupportedChains();
const swapChains = chains.filter((chain) => chain.capabilities.intent);
console.log(swapChains.map((chain) => `${chain.name} (${chain.id})`));
```

## Step 3: Attach a wallet provider

`setEVMProvider()` attaches an EIP-1193 provider and reads the connected account. Call it after the user has connected their wallet.

```typescript title="TypeScript"
import type { EthereumProvider } from "@avail-project/nexus-core";

const provider = (window as any).ethereum as EthereumProvider | undefined;
if (!provider) throw new Error("Install an EIP-1193 wallet such as MetaMask");

await provider.request({ method: "eth_requestAccounts" });
await client.setEVMProvider(provider);

console.log(client.hasEvmProvider); // true
```

`client.hasEvmProvider` is `true` once a provider is attached.

<Callout type="info" title="Using a wallet library?">
This guide uses `window.ethereum` for simplicity. With wagmi or RainbowKit, get the provider from the active connector with `connector.getProvider()`. See [Initializing Nexus with RainbowKit](/docs/nexus/nexus-sdk/get-started/initializing-nexus-with-rainbowkit).
</Callout>

### What needs a wallet

| Works after `initialize()`, no wallet | Needs `setEVMProvider()` |
| --- | --- |
| `getSupportedChains()`, `isSupportedChain()` | `getBalances()` |
| `getTokens()`, `getTokensByChain()`, `getToken()` | `swapWithExactOut()` and `swapAndExecute()` |
| `getAvailableSourceTokens()`, `getAvailableDestinationTokens()` | Executing `swapWithExactIn()` |
| `confirmRouteExists()`, `getSupportedChainsForRoute()` | `execute()` and `simulateExecute()` |
| Exact-input quote previews with `swapWithExactIn()` and `hooks.onIntent` | |

A `swapWithExactIn()` call started without a wallet can show a quote in your review UI, but it cannot complete. After the user connects, start a new call. See [Review quotes](/docs/nexus/nexus-sdk/reference/swap-methods/review-quotes).

## Step 4: Fetch balances

`getBalances()` returns the connected wallet's token balances across all supported chains. Amounts are raw `bigint` values; format them with each token's own `decimals`.

```typescript title="TypeScript"
import { formatUnits } from "@avail-project/nexus-core/utils";

const balances = await client.getBalances();
for (const balance of balances) {
  console.log(
    balance.chainId,
    balance.symbol,
    formatUnits(balance.usableBalanceRaw, balance.decimals), // available for routing
    formatUnits(balance.actualBalanceRaw, balance.decimals), // full wallet balance
    balance.valueUsd, // USD value of the usable balance, or null
  );
}
```

`usableBalanceRaw` is what the SDK can route after gas reserves; `actualBalanceRaw` is the full wallet balance. See [Get balances](/docs/nexus/nexus-sdk/reference/balances-and-tokens/get-balances) for every field.

## Lifecycle: account changes and cleanup

A client is bound to the account that was connected when you called `setEVMProvider()`. Follow these rules:

- **Recreate the client when the account or provider changes.** Call `destroy()` on the old client, then create, initialize, and attach the provider to a new one. Calling `setEVMProvider()` again with the same provider object does not pick up a new account.
- **Call `client.destroy()` on cleanup**, for example when the user disconnects or your component unmounts.

Here is a small module that puts this together using `window.ethereum`:

```typescript title="src/lib/nexus.ts"
import {
  createNexusClient,
  type EthereumProvider,
  type NexusClient,
} from "@avail-project/nexus-core";

let client: NexusClient | null = null;

export async function connectNexus(provider: EthereumProvider): Promise<NexusClient> {
  client?.destroy();
  const next = createNexusClient({ clientId: "my-nexus-app", network: "mainnet" });
  await next.initialize();
  await next.setEVMProvider(provider);
  client = next;
  return next;
}

export function disconnectNexus(): void {
  client?.destroy();
  client = null;
}

export function getNexusClient(): NexusClient {
  if (!client) throw new Error("Connect a wallet first");
  return client;
}

// Recreate the client whenever the wallet switches accounts.
export function watchAccounts(provider: EthereumProvider): () => void {
  const onAccountsChanged = (...args: unknown[]) => {
    const accounts = args[0] as string[];
    if (accounts.length === 0) disconnectNexus();
    else void connectNexus(provider);
  };
  provider.on("accountsChanged", onAccountsChanged);
  return () => provider.removeListener("accountsChanged", onAccountsChanged);
}
```

In a React app, put the same logic in an effect keyed on the connected account and return `destroy()` from its cleanup. The [RainbowKit guide](/docs/nexus/nexus-sdk/get-started/initializing-nexus-with-rainbowkit) shows a complete hook.

## Analytics

The SDK sends product analytics by default. In the default `mode: 'auto'`, analytics are also skipped outside the browser, on localhost, and when `NODE_ENV` is `test`, `ci`, or `development`. To opt out entirely:

```typescript title="TypeScript"
const client = createNexusClient({
  clientId: "my-nexus-app",
  analytics: { enabled: false },
});
```

Diagnostic logging is configured separately. See the [utility reference](/docs/nexus/nexus-sdk/reference/utility-reference) for the full client configuration.
