Install and initialize the client first — see [Installation](/docs/nexus/nexus-sdk/get-started/installation) and [SDK Setup](/docs/nexus/nexus-sdk/get-started/nexus-sdk-setup).

[`swapWithExactIn`](/docs/nexus/nexus-sdk/reference/swap-methods/swap-exact-in) and [`swapWithExactOut`](/docs/nexus/nexus-sdk/reference/swap-methods/swap-exact-out) accept an `onEvent` callback in `SwapOperationOptions`. It receives a typed `IntentEvent` that you can narrow on `event.type`.

[`swapAndExecute`](/docs/nexus/nexus-sdk/reference/swap-methods/swap-and-execute) emits the same intent events for its funding swap. Its promise also covers the contract call that follows.

## Method signature

```typescript title="TypeScript"
type SwapOperationOptions = {
  onEvent?: (event: IntentEvent) => void;
  // hooks, slippageBps, fillTimeoutMinutes, pollingIntervalMs — see Review Quotes
};

export type IntentEvent =
  | { type: 'quote'; quote: IntentQuote }
  | {
      type: 'step';
      step: IntentPlanStep;
      state: IntentStepState; // 'started' | 'completed' | 'failed'
      committed: boolean;
      /** @deprecated Use `errorDetails.message`. Kept for backwards compatibility. */
      error?: string;
      errorDetails?: IntentStepError;
    }
  | {
      type: 'status';
      status: IntentLifecycleStatus; // 'created' | 'deposited' | 'fulfilled' | 'expired'
      substatus: string;
      intentId: Hex;
      legs: IntentLegStatus[];
    };
```

## Parameters

### `quote` events

Emitted when the first quote arrives, and again whenever [`refresh()`](/docs/nexus/nexus-sdk/reference/swap-methods/review-quotes#refresh) returns a replacement. The event is emitted even without a review hook, so you can show the quote and its `plan.steps` before execution starts. `IntentQuote` fields are documented on [Review Quotes](/docs/nexus/nexus-sdk/reference/swap-methods/review-quotes#intentquote).

### `step` events

Emitted as each step of the accepted quote's `plan` starts, completes, or fails.

- `step`: the `IntentPlanStep` from `quote.plan.steps` (match on `step.id` to update a progress list).
- `state`: `'started'`, `'completed'`, or `'failed'`.
- `committed`: `true` once the intent can no longer be cancelled locally. That happens after the intent signature when any source is an ERC-20, or when a native source transaction is broadcast. A failure with `committed: true` may still settle, so check the intent's status before retrying.
- `errorDetails` (on `'failed'`): structured error details. Use it instead of the deprecated `error` string.

```typescript title="TypeScript"
export type IntentStepError = {
  name: string;
  message: string;
  category?: ErrorCategory;
  code?: ErrorCode;
  service?: string;
  stepId?: string;
  stepType?: string;
  chainId?: number | string;
  details?: Record<string, unknown>;
};
```

### Plan steps

```typescript title="TypeScript"
export type IntentPlanStep =
  | {
      id: string;
      type: 'erc20_approval' | 'source_approval_signature';
      chainId: number;
      tokenAddress: Hex;
      spender: Hex;
      amountRaw: bigint;
    }
  | { id: string; type: 'intent_signature' }
  | {
      id: string;
      type: 'native_transaction';
      chainId: number;
      sourceIndex: number;
      to: Hex;
      valueRaw: bigint;
    }
  | { id: string; type: 'intent_submission' }
  | { id: string; type: 'intent_fulfillment' };
```

| Step type | What happens |
| --- | --- |
| `erc20_approval` | The wallet sends an ERC-20 `approve` for the minimum required amount. |
| `source_approval_signature` | The wallet signs a permit instead of sending an approval transaction. |
| `intent_signature` | The wallet signs the intent. |
| `native_transaction` | The wallet sends a native-token source deposit (one per native source). |
| `intent_submission` | The SDK submits the signed intent. |
| `intent_fulfillment` | The SDK polls until the intent is fulfilled, expires, or times out. |

Steps that aren't needed, such as approvals when the allowance is already sufficient, may not emit events.

### `status` events

Emitted on every fulfillment poll (every `pollingIntervalMs`, default 2000 ms), until the intent reaches `fulfilled` or `expired`.

```typescript title="TypeScript"
export type IntentLegStatus = {
  sourceIndex: number;
  status: IntentLifecycleStatus;
  txHash?: Hex;
  txExplorerUrl?: string;
  protocolExplorerUrl?: string;
  error?: string;
};
```

- `intentId`: the intent (quote) ID.
- `status`: `created`, `deposited`, `fulfilled`, or `expired`. The same values are available at runtime as the exported `IntentStatus` constant.
- `substatus`: a provider-specific detail string.
- `legs`: per-source progress, with transaction links and errors.

### Callback failures are non-blocking

If your `onEvent` callback throws, the SDK logs the failure and the operation continues. Event handlers are for progress UI; always handle the final outcome through the promise.

## Example

```typescript title="TypeScript"
import type { IntentEvent, SwapOperationOptions } from '@avail-project/nexus-core';
import { parseUnits } from '@avail-project/nexus-core/utils';

const onEvent = (event: IntentEvent): void => {
  switch (event.type) {
    case 'quote':
      console.log('Quote', event.quote.output, event.quote.fees, event.quote.plan.steps);
      break;
    case 'step':
      console.log('Step', event.step.id, event.step.type, event.state);
      if (event.state === 'failed') {
        console.error(event.errorDetails?.message, event.errorDetails?.code);
        // A committed attempt may still settle; check its status before retrying.
        console.log('Committed', event.committed);
      }
      break;
    case 'status':
      console.log('Intent', event.intentId, event.status, event.substatus);
      for (const leg of event.legs) {
        console.log('Source', leg.sourceIndex, leg.status, leg.txExplorerUrl, leg.error);
      }
      break;
  }
};

const options: SwapOperationOptions = { onEvent };
const destination = {
  chainId: 8453,
  tokenAddress: '0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913', // USDC on Base
} as const;
const destinationToken = await client.getToken(destination);

try {
  const result = await client.swapWithExactOut(
    {
      toChainId: destination.chainId,
      toTokenAddress: destination.tokenAddress,
      toAmountRaw: parseUnits('10', destinationToken.decimals),
    },
    options,
  );
  console.log('Fulfilled', result.intentExplorerUrl, result.attemptId);
} catch (error) {
  console.error('Swap failed', error);
}
```

## Return Value: `IntentResult`

Both swap methods resolve after fulfillment with an `IntentResult` (also exported as `SwapResult`).

```typescript title="TypeScript"
export type IntentResult = {
  /** SDK payment attempt correlation ID; shared across quote refreshes. */
  attemptId?: string;
  intentId: Hex;
  intentExplorerUrl: string;
  quote: IntentQuote;
  status: IntentStatus; // exported as IntentStatusResponse
  approvals: IntentTransaction[];
  nativeTransactions: IntentTransaction[];
};

export type IntentTransaction = {
  chainId: number;
  txHash: Hex;
  txExplorerUrl: string;
  receipt?: TransactionReceipt;
};
```

- `intentId`: the fulfilled intent's ID.
- `intentExplorerUrl`: a link to the intent in the Nexus explorer.
- `quote`: the quote that was accepted and executed.
- `status`: the final status response (`id`, `provider`, `status`, `substatus`, `legs`). Note that the root-exported `IntentStatus` type is the lifecycle-string union; this object shape is exported as `IntentStatusResponse`.
- `approvals`: approval transactions sent during this operation.
- `nativeTransactions`: native-token source deposits sent during this operation.
- `attemptId`: an SDK correlation ID, shared across refreshes. Store it with `intentId` for support.

<Callout type="warn">
A rejected promise may follow transactions that were already submitted. After a timeout or connection failure following commitment, check [`listIntents`](/docs/nexus/nexus-sdk/reference/list-intents), the explorer, and known transaction hashes before retrying. Approval failures can expose `error.details.approvals`. See [Hooks and Errors](/docs/nexus/nexus-sdk/reference/hooks-and-errors) and the [type definitions](https://github.com/availproject/nexus-sdk/blob/main/src/intent/types.ts) on GitHub.
</Callout>
